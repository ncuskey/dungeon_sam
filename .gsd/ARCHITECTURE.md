## Overview

**Dungeon Sam** is a browser-based, first-person 3D dungeon crawler built with React + Three.js. The player explores a procedurally generated dungeon, fights enemies, collects items, and must find the exit. It is deployed as a static Vite SPA to https://dungeonsam.site.

## Components

- **Purpose:** Root compositor. Renders all top-level components, gates mobile controls behind `isMobile` flag.
- **Location:** `src/App.tsx`
- **Dependencies:** `GameCanvas`, `PlayerController`, `HUD`, `GameOverlay`, `WeaponOverlay`, `TouchControls`, `Minimap`, `useGameStore`

### `GameCanvas`
- **Purpose:** Hosts the React Three Fiber `<Canvas>`. Starts the game loop via `useGameLoop`, provides ambient lighting, and renders `LevelRenderer`, `EnemyRenderer`, and child `ItemRenderer`.
- **Location:** `src/components/GameCanvas.tsx`
- **Dependencies:** `@react-three/fiber`, `LevelRenderer`, `EnemyRenderer`, `CameraRig`, `useGameLoop`

### `LevelRenderer`
- **Purpose:** The 3D dungeon. Renders walls (box meshes), a floor & ceiling plane, doors (pivot-based hinged boxes), and torch lights (Billboard sprites + PointLights). Torches select front/left/right sprite based on camera angle.
- **Location:** `src/components/LevelRenderer.tsx`
- **Dependencies:** `@react-three/fiber`, `@react-three/drei`, `three`, `textureGenerator`, `Billboard`, `gameStore`

## Utilities

### `dungeonGenerator.ts`
- **Algorithm:** Binary Space Partitioning (BSP) — 30×30 grid, splits into leaves of 6–12 cells, assigns rooms, L-shaped corridors between siblings.
- **Doors:** Placed at floor cells with exactly opposing walls (N-S or E-W) at 15% probability.
- **Spawning:** 1 Sword of Truth (random non-start room), health potions (2% per floor cell, ≤2 per room), enemies per room (50% chance).

### `ai.ts`
- **Algorithm:** Greedy Manhattan distance minimization. Enemies stay adjacent (don't dance), can't share cells, pathfind around walls. Imps move every 2 ticks, Goblins every 1 tick.

### `textureGenerator.ts`
- **Purpose:** Procedurally generates wall, floor, and ceiling textures via Canvas 2D API. No external texture files for world geometry.

## Data Flow

1. `main.tsx` mounts React, `dungeonGenerator` runs once at module load to seed initial state
2. `useGameLoop` fires `tickGame` every frame → enemies move, damage applied, phase checked
3. `PlayerController` / `TouchControls` dispatch store actions on input
4. All renderers (`LevelRenderer`, `EnemyRenderer`, etc.) subscribe reactively to Zustand store slices
5. `CameraRig` reads `playerPosition`, `playerDirection`, `shake` every frame via `useFrame`
6. Audio events are fired imperatively from store actions (not reactive)
